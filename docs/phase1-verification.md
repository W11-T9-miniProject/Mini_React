# Phase 1 검증 기록

- 검증일: 2026-11-07
- 환경: Windows, Node.js 26.13.0, npm 11.20.0, Chrome(headless).
- 팀 지정 Node.js는 24.x입니다. 이번 기록은 26.x에서 실행한 결과이며, 24.x 검증 결과를 대신하지 않습니다.

## 자동 검사

`npm run check`는 Prettier 검사 → Vitest → Vite 빌드를 실행합니다.

- 7개 테스트 파일, 62개 테스트 통과. `it.todo` 없음.
- DOM 변환: 요소·속성·중첩·텍스트·공백 보존·주석 제외.
- DOM 생성: 요소·자식·속성 생성, 왕복 변환.
- Diff: 다섯 변경 종류·경로·위치 비교·입력 불변성.
- Patch: 노드 유지·연속 삭제·중간 삽입·루트 교체·다섯 명령 연결.
- History: 경계·분기·저장 데이터 복사.
- 화면 통합: 미리보기와 실제 영역 분리·반복 Patch·HTML 편집·미지원 입력 거부·일반 텍스트 붙여넣기·이력 이동·미저장 편집 취소·루트 교체 후 다음 Patch.

## 실제 브라우저 확인

임시 Playwright 실행 환경에서 로컬 Vite 서버를 대상으로 Chrome을 실행했습니다. Playwright는 프로젝트 의존성에 추가하지 않았으며, 아래 브라우저 검증 스크립트는 저장소의 자동 검사에 포함되지 않습니다.

- HTML 편집 → 미리보기 → Patch 후 실제 요소 생성.
- 실제 영역은 Patch 전까지 유지.
- 직접 문장 편집과 Patch, 연속 Patch.
- 뒤로·앞으로 이동 시 실제 영역·테스트 영역·HTML 입력창 동기화.
- 미저장 편집 취소, 뒤로 이동 후 새 저장 시 미래 이력 제거.
- 오타 태그 입력 시 기존 미리보기 유지 및 오류 안내.
- 루트 태그 교체 이후에도 이력과 다음 Patch 동작.
- 새로고침 시 이력 초기화.
- 초기 두 영역의 상자 및 내용 기준선 정렬.
- 밝은/어두운 모드, 너비 320·390·768·1280px에서 가로 넘침 없음.
- 테스트 중 처리되지 않은 페이지 JavaScript 오류 없음.

## 직접 재확인 순서

1. `npm ci` 후 `npm run check` 실행.
2. `npm run dev`로 브라우저 열기.
3. HTML 입력창에 `<article><p class="greeting">A</p><button>클릭</button></article>` 입력.
4. 미리보기 적용 후 실제 영역이 아직 유지되는지 확인하고 Patch 클릭.
5. A를 B로 바꾸고 Patch. 뒤로가기·앞으로가기로 양쪽이 함께 이동하는지 확인.
6. 뒤로 간 뒤 D로 바꿔 저장하고 앞으로가기 비활성화 확인.
7. `<buton>` 같은 태그를 입력하고 기존 화면 유지·오류 안내 확인.
8. 모바일 폭에서 두 영역·입력창·버튼이 화면 밖으로 넘치지 않는지 확인.
