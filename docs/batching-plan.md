# 명시적 배칭 구현·검증 계획

- 날짜: 2026-11-09
- 기존 합의: `batch(() => { ... })`로 시작하고 기존 즉시 갱신 동작은 유지한다. 비교를 마친 뒤 Redis로 진행한다.
- 브랜치: `JSZeroDev/react`. 커밋·푸시는 사용자가 터미널에서 수행한다.

## 범위와 계약

- `src/component/function-component.js`에서 `batch(callback)`을 내보낸다. 상태는 setter 호출 때 저장하고, 갱신 대상 루트를 중복 없이 모아 가장 바깥 동기 콜백이 끝날 때 한 번씩 갱신한다.
- 중첩 배칭·같은 상태의 함수형 연속 변경·동일 값·여러 루트·언마운트를 다룬다. `await` 뒤까지 묶는 자동 배칭은 구현하지 않는다.
- 콜백 예외가 발생해도 이미 수행한 setter는 반영하고 예외를 전달한다. 트랜잭션은 아니다. 지연된 렌더가 커밋 전에 실패하면 해당 루트의 이전 상태를 복원한다. 다른 루트의 갱신은 계속 처리하며 오류를 전달한다.
- 기존 렌더 중 상태 변경 거절, 오래된 setter 거절, Effect 후속 갱신·오류 처리 규칙을 유지한다.
- 비교 화면은 같은 장바구니 표시, 동일 입력을 사용하는 즉시 갱신과 배칭 갱신을 나란히 배치한다. `useEffect`에서 실제 커밋 결과와 해당 Patch 수를 수집한다. 초기 mount는 횟수에서 제외한다.
- 쿠폰 할인과 안내 변경은 갱신 2회/1회이며 최종 결제 금액이 같다. 연속 함수형 변경은 화면 체험에 노출하지 않고 엔진 테스트에서 확인한다. DOM 명령 수가 줄어든다고 가정하지 않는다.
- 이는 엔진 갱신·DOM 반영의 비교이며 브라우저 Paint 횟수나 실제 React 전체의 성능을 측정하지 않는다.

## 확인 결과

- 엔진 12개·비교 화면 6개 신규 테스트와 기존 검증을 포함해 17개 파일·128개 테스트를 확인한다. 최종 결과는 npm run check 실행 로그를 기준으로 한다.
- 브라우저에서 쿠폰 변경 2/1회, 단일 변경 1/1회와 390px 세로 배치를 확인했다.
- 학습자의 체험·설명 및 커밋·푸시는 아직 진행하지 않았다.

- 사용자 피드백 반영: 단일 상태 변경 버튼을 첫 화면에서 치우고, 실제 중간/최종 갱신 기록을 먼저 보여준다. 기존 실험과 상세 정보는 접어서 필요한 경우에만 읽는다.

- 추가 사용자 피드백: 세 실험을 상태 관리→계산 재사용→배칭(선택) 순서의 동등한 접기/펼치기로 통일했다. 배칭 기록은 문장만 나열하지 않고 작은 화면의 숫자·두 배·요약 및 실제 변경 위치를 표시한다.

- 최종 예시는 무선 마우스 장바구니로 교체했다. 수량·배송 요청·쿠폰 할인·독립적으로 닫는 안내를 사용하며 이름/두 배 예시와 일부러 고장 내는 체험은 제거했다. 성능 실험은 상품별 금액 합계와 배송 요청 재사용을 비교한다.

- 생활 예시와 무관한 ‘수량 +1 세 번’ 체험은 제거했다. 쿠폰 할인·안내라는 두 상태 변경으로만 배칭의 핵심을 비교하며 엔진의 함수형 누적 검증은 유지한다.

## 최종 예시 매칭 기준

- 비교 목적을 먼저 정하고, 같은 입력과 최종 결과를 유지하는 정상 구현끼리 비교한다.
- Phase 1 상품 수량 변경: 전체 DOM 교체와 부분 수정·입력 요소 재사용을 확인한다.
- Phase 2 상태 관리: 수량에 따른 금액 갱신을 직접 DOM 코드로 연결하는 방식과 상태 기반 엔진을 비교한다. 속도 승패를 주장하지 않는다.
- Phase 2 계산 재사용: 가격과 무관한 배송 요청 변경에서 합계를 재사용하고, 수량 변경에서는 다시 계산한다. 작은 장바구니에서 차이가 작거나 캐시가 불리할 수 있다.
- Phase 2 배칭: 쿠폰 적용이라는 사용자 행동 한 번으로 할인과 독립적인 안내 상태가 바뀌는 예시만 사용한다. 다른 예시는 중복 추가하지 않는다.
- 일부러 고장 내기와 ‘수량 +1 세 번’은 사용자 화면에 넣지 않는다. 연속 함수형 갱신은 내부 엔진 테스트로 유지한다.
- 화면은 예시·조작·관찰 지점을 짧게 안내하고, 코드·측정 한계는 접어 둔다. 사람의 설명 여부는 기능 테스트 통과와 구분한다.

## 조작과 결과 배치 개선

- 공통 조작 버튼 → 이번 갱신 횟수 → 현재 장바구니 순서로 배치한다.
- 버튼은 스크롤 중에도 상단에 남으며 양쪽에 같은 작업을 적용한다.
- 마지막 작업에서 실제로 바뀐 필드만 강조하고, 다음 작업이나 초기화 때 이전 강조를 지운다.
- 중간 갱신 기록과 코드·상세 수치는 기본적으로 접는다. 진단용 강조는 Patch 계측에 포함하지 않는다.
