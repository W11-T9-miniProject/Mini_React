# Node World 브라우저 확인

`npm run dev`로 앱을 열고 Node World 단일 화면에서 확인합니다. jsdom 통과만으로 브라우저의 글자 크기·반응형 동작을 대신하지 않습니다.

## 단일 화면과 발표 가독성

- 처음 열면 Node World가 바로 나타나고 왼쪽 메뉴나 다른 페이지가 없어야 합니다.
- 제목, 작업 버튼, 패널 안내가 발표 거리에서도 읽히는 크기인지 확인합니다.
- 브라우저 폭을 데스크톱, 태블릿, 약 390px로 바꿔도 버튼과 비교 카드가 겹치거나 페이지 바깥으로 넘치지 않아야 합니다.
- 이전·다음 VDOM의 전체 노드 캐릭터가 각 패널 안에 자동 맞춤되는지 확인합니다. 창 크기를 조절하면 트리가 다시 맞춰져야 합니다.
- Tab으로 버튼, 모드 선택, 노드 캐릭터를 이동하고 포커스 표시를 확인합니다. 운영체제의 모션 감소 설정도 확인합니다.

## 같은 상태 변경, 두 렌더 방식

- 비교 카드는 변경 버튼 바로 아래에 보여야 합니다.
- 기본 단계별 모드에서 실제 DOM을 읽고 텍스트/속성/노드 추가·삭제·교체·이동을 수행합니다. 직접 DOM 미리보기는 상태 입력 즉시 전체 하위 트리를 새로 만들고, 실제 대상 DOM은 Patch 전까지 그대로여야 합니다.
- Diff 단계 재생에서 이전/신규 VDOM 노드가 만나고, 변경 명령을 수집해야 합니다. 변경 없는 노드는 실제 Patch를 만들지 않습니다.
- Patch 배달부를 누르면 실제 `patch()`가 실행되고 DOM 재사용·생성·삭제 수가 표시되어야 합니다.
- 자동 실행 모드를 켜면 한 번의 입력에서 직접 DOM 전체 재생성과 실제 VDOM Diff/Patch가 실행되어야 합니다. VDOM 캐릭터의 교체·이동 애니메이션은 유지되고, 애니메이션 시간을 엔진 속도로 안내하지 않아야 합니다.

## State와 Effect

- `State +3`은 숫자 +3, Memo 값 +6, 렌더 1회 증가를 표시해야 합니다.
- Effect 로그에서 의존성 변경 시 이전 cleanup 다음 새 effect가 실행되어야 합니다.
- 처음부터 버튼을 누르면 현재 Effect cleanup을 실행하고 모든 지연 애니메이션을 취소해야 합니다.

브라우저에서 직접 확인한 결과는 자동 빌드나 테스트 실행 결과와 별도로 기록합니다.

## 고정 상품 수량 변경 성능 비교

- 페이지 하단에서 상품 100개 중 첫 상품 수량을 1개에서 2개로 바꿉니다. 배송 요청 입력은 포함하지 않습니다.
- 직접 DOM은 새 목록 전체를 만들고 교체해야 합니다. 생성/삭제 Element 101개, 유지한 상품 li 0개, 텍스트 수정 0개를 표시해야 합니다.
- VDOM은 실제 Diff·Patch로 수량 속성과 문구를 바꿔야 합니다. 상품 li 100개를 유지하고, 새/삭제 Element 0개, 기존 텍스트 수정 1개, PROPS + TEXT 명령 2개를 표시해야 합니다.
- 비교 버튼 한 번에 각 렌더 방식을 한 번씩 재고, 다음 실행에서는 순서를 바꿉니다. 막대그래프와 표의 처리 시간은 측정값과 일치해야 합니다.
- 작은 화면에서 그래프와 결과 표는 가로로 읽을 수 있어야 하며, 페이지 전체 가로 넘침이 없어야 합니다.
