# 실제 브라우저 기능 확인

npm run dev로 시작하고 터미널에 표시된 주소를 엽니다. 아래 결과를 직접 확인하세요. jsdom 통과만으로 브라우저 레이아웃/IME 검증을 대신하지 않습니다.

## Phase 1

| 단계 | 조작                                         | 기대 결과                                          |
| ---- | -------------------------------------------- | -------------------------------------------------- |
| 1    | 초기 화면                                    | 두 영역의 샘플이 같고 상태 1/1, 이력 버튼 비활성화 |
| 2    | 직접 편집으로 문장 수정                      | 테스트만 변경, 미적용 표시, HTML/VDOM 표시 갱신    |
| 3    | Patch                                        | 실제 문장 변경, TEXT 표시, 상태 2/2                |
| 4    | 같은 상태에서 다시 Patch                     | 변경 없음, 상태 수 유지                            |
| 5    | 코드에서 title 추가 후 Patch                 | PROPS, 실제 속성 추가                              |
| 6    | title 제거 후 Patch                          | remove에 title, 실제 속성 제거                     |
| 7    | h3를 h2로 바꾸고 Patch                       | REPLACE, 새 태그                                   |
| 8    | 마지막 li 2개 추가 후 Patch                  | INSERT, 목록 증가                                  |
| 9    | li 여러 개 삭제 후 Patch                     | REMOVE, 정확한 항목 수                             |
| 10   | 뒤로/앞으로                                  | 실제/테스트/HTML이 선택한 상태로 일치              |
| 11   | 뒤로 간 뒤 새 변경 Patch                     | 미래 이력 제거, 앞으로 비활성화                    |
| 12   | 미적용 문장을 만든 뒤 뒤로                   | 미적용 편집도 목표 이력으로 덮어쓰기               |
| 13   | 코드 전체 삭제 후 Patch                      | 빈 샘플 루트, 오류 없이 복구 가능                  |
| 14   | input/checkbox/select/textarea 편집 후 Patch | 현재 value/checked/선택값이 실제 영역에 반영       |
| 15   | script/onerror/javascript URL 입력           | 오류 표시, 실제 DOM/이력 보존                      |
| 16   | 오류 후 올바른 HTML 입력                     | 편집 복구, 다시 Patch 가능                         |
| 17   | 샘플 불러오기                                | 테스트만 샘플 복원, Patch 전 실제 영역 유지        |

HTML 파서는 브라우저 규칙에 따라 잘못 중첩된 태그를 보정합니다. img/a는 일반 URL만 사용하세요. 편집 영역의 링크 클릭은 페이지 이동을 막습니다. style 대신 class를 사용합니다.

## Phase 2

| 단계 | 조작                    | 기대 결과                                   |
| ---- | ----------------------- | ------------------------------------------- |
| 1    | Component Studio 선택   | 초기 작업 3개, 전체 3/완료율 33%, 타이머 0s |
| 2    | 새 작업 입력 후 Enter   | 작업 추가, 입력 초기화, 제출 시 렌더 +1     |
| 3    | 빈칸만 입력             | 추가 버튼 비활성화, 추가 안 됨              |
| 4    | checkbox 클릭           | 완료율/취소선/제목 변경                     |
| 5    | 완료/진행 중 필터       | 해당 작업만 표시                            |
| 6    | 검색어 입력             | 제목이 일치하는 작업만 표시                 |
| 7    | 결과 없는 검색          | 빈 상태 표시                                |
| 8    | 삭제/완료 작업 삭제     | 목록과 통계 일치                            |
| 9    | 입력 중 다른 상태 갱신  | 입력 노드와 커서 유지                       |
| 10   | +3 배칭 테스트          | 타이머 값 +3, 렌더 +1, Memo 계산 유지       |
| 11   | 타이머 시작 후 2초 이상 | 초 증가, 렌더 증가, Memo 계산 유지          |
| 12   | 타이머 정지 후 기다리기 | 초 증가 중지, cleanup 로그                  |
| 13   | 시작/정지 반복          | interval 중복 없이 초당 +1                  |
| 14   | 타이머 실행 중 Unmount  | 화면 비워짐, interval 해제/제목 복원        |
| 15   | 다시 Mount              | 초기 작업과 타이머로 시작                   |
| 16   | 한글 조합 입력          | 조합이 끊기지 않고 입력/추가 가능           |

렌더 진단의 마지막 Patch에는 이벤트 함수 참조 변경도 포함됩니다. 필터/삭제 시 인덱스 기반 비교로 항목 DOM을 재사용하므로 key 기반 이동을 구현했다고 설명하지 않습니다.

## 브라우저 내장 검사와 반응형

1. 코드 따라가기 → 12개 검사 실행 → 전부 PASS.
2. 다시 실행 → 같은 결과, 기존 실습 작업/이력 유지.
3. 개발자 도구에서 콘솔 오류 확인.
4. 창을 약 390px로 줄이기 → 메뉴가 위로 이동, 패널이 한 열, 가로 페이지 넘침 없음.
5. Tab으로 메뉴/버튼/입력/편집기 이동 → 포커스 표시 확인.
6. Phase 1과 Phase 2를 오가도 상태가 유지되는지 확인.
7. 새로고침하면 모든 이력과 작업이 초기화되는지 확인.

이 문서는 재현할 절차이며, 각 항목이 실제 브라우저에서 실행됐다는 기록을 의미하지 않습니다.
