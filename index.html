입력칸에 남아 있는 메모 작성 중인 메모 작성 중인 메모

‘기존 요소의 글자만 수정 0개’는 최종 글자가 바뀌지 않았다는 뜻이 아닙니다. 전체 교체는 바뀐 글자를 담은 새 요소를 만들므로 생성 작업으로 집계합니다. 전체 요소 수에는 목록 ul과 메모 input도 포함하며 텍스트 노드는 제외합니다.

이 메모는 입력칸 자체에 보관한 값입니다. HTML 구조가 같아도 입력칸에 현재 남은 값은 다를 수 있습니다. 전체 교체 방식도 메모를 별도 상태에 저장하고 복원하면 보존할 수 있습니다. 이 실험은 기존 DOM을 재사용하는 효과를 보여줍니다. 실제 React의 상태·컴포넌트 관리 이점은 Phase 2에서 이어서 확인합니다.

시간 단위 ms는 1/1,000초입니다. 비교 실행 시 두 방식의 실제 작업을 한 번씩 자동 측정합니다. 측정용 목록을 추가로 만들거나 반복 실행하지 않습니다. 실행 순서는 매번 교대합니다. 전체 교체는 새 DOM 생성·교체, Diff·Patch는 차이 계산·DOM 수정 시간을 포함합니다. 공통 VDOM 입력 준비·색상 표시·결과 검사는 제외합니다.

이 시간은 실제 결과 영역을 수정하는 JavaScript·DOM 처리 구간입니다. 변경 후 브라우저가 수행하는 배치 계산·화면 그리기를 포함한 전체 시간은 아닙니다. 단일 측정은 편차가 크고, 작은 값은 측정 해상도 때문에 0.000 ms로 나올 수 있습니다. 같은 조건을 다시 확인하려면 처음 상태로 돌아간 뒤 실행하세요.

Diff가 계산한 변경 명령 
[]

전체 교체는 React를 사용하지 않는 모든 방식을 대표하지 않습니다. 직접 DOM을 부분 수정하는 방법도 있습니다. Diff는 비교 계산 비용이 있어 항상 더 빠른 것은 아닙니다. 이 결과는 이 Mini React 구현과 현재 실험 조건에 대한 결과입니다.

상태를 바꾸면, 여러 표시가 함께 바뀝니다.

숫자 +1을 누르면 숫자·두 배·요약 문장이 함께 갱신됩니다. 이름 바꾸기는 이름 상태만 바꿉니다. 이 탭에서는 Patch 버튼을 따로 누르지 않습니다.

클릭 → 상태 변경 함수 → hooks의 자기 칸 저장 → 컴포넌트 재실행 → 기존 Diff·Patch

useEffect · 숫자가 바뀌면 탭 제목도 갱신

숫자 +1을 누른 뒤 실제 브라우저 탭 제목을 확인하세요. 이름만 바꾸면 이 작업은 다시 실행하지 않습니다. 처음 화면을 만들 때도 한 번 실행합니다.

실행 횟수: 0회 · 의존값: []

탭 제목:

Effect의 의존값·정리 함수는 hooks[2]에 보관합니다. 이 실행 정보는 학습용 표시로 별도 갱신하며, 위 Patch 명령 개수에는 포함하지 않습니다.

useMemo · 이름만 바꾸면 계산 결과 재사용

위의 이름 바꾸기를 누르면 컴포넌트는 다시 실행됩니다. 일반 계산은 다시 수행하지만, useMemo는 숫자가 같으면 저장된 두 배 값을 사용합니다. 숫자 +1을 누르면 두 방식 모두 다시 계산합니다.

현재 계산 결과 0 0
계산 함수 실행 횟수 0 0

캐시된 결과와 의존값은 hooks[3]에 저장합니다. 첫 계산은 두 방식 모두 실행합니다. 이 계산은 매우 가벼워 실무에서 굳이 캐시할 필요는 없습니다. 속도 향상을 주장하는 예제가 아니라 재계산과 재사용을 횟수로 확인하는 실습입니다. 이 표도 학습용 표시로 별도 갱신하며 Patch 명령 수에 포함하지 않습니다.

                  일반 변수 변경 후 갱신 함수를 직접 호출합니다. 함수 안에서
                  숫자·두 배·요약 DOM을 각각 찾아 씁니다.
                
                
                  useState로 상태를 바꾸면 컴포넌트를 다시 실행합니다. 현재
                  상태로 화면을 정의하면 Phase 1의 Diff·Patch가 반영합니다.
                
              

              

                이름만 바꿀 때 두 배 계산
                
                  이 예제의 공통 갱신 함수는 매번 계산합니다. 필요하면 직접
                  캐시를 추가할 수도 있습니다.
                
                
                  useMemo의 [count]가 같으면 이전 결과를 재사용합니다.
                  컴포넌트는 다시 실행됩니다.
                
              

              

                숫자가 바뀔 때 외부 제목 갱신
                이전 숫자를 변수에 보관하고 if 조건으로 비교합니다.
                
                  useEffect에 [count]를 지정합니다. 엔진이 의존값을 비교해 DOM
                  반영 후 실행합니다.
                
              

              

                화면을 닫을 때 외부 구독 해제
                닫기 함수에서 구독 해제 함수를 직접 호출합니다.
                
                  useEffect가 반환한 정리 함수를 엔진이 unmount 때 호출합니다.
                
              

            
          

          

            알림은 이 페이지 안의 실제 이벤트 구독입니다. ‘채팅 알림 보내기 → 두
            화면 닫기 → 다시 알림 보내기’로 확인하세요. 양쪽 모두 구독이 0개가
            되고 수신 횟수가 더 늘지 않아야 정상입니다. 외부 제목은 두 방식이
            같은 브라우저 제목을 덮어쓰지 않도록 각 카드에서 미리보기로
            보여줍니다.
          

          

            React 없이도 DOM API나 jQuery로 이런 일을 직접 연결해 왔습니다. 공통
            갱신 함수·다른 프레임워크로 관리하는 방법도 있으므로 왼쪽이 모든
            기존 방식을 대표하지는 않습니다. 작은 화면은 직접 관리가 더 단순할
            수 있습니다. React 방식은 상태·화면·외부 작업의 관계를 모아 관리하기
            좋지만, 엔진과 규칙을 배우고 VDOM 비교·의존값 검사·캐시 비용을
            부담합니다. 숫자 × 2는 캐시가 필요 없을 만큼 가볍습니다. 이 실험은
            관리 책임과 실행 횟수 비교이며 속도 우위를 증명하지 않습니다.
