추가 설명 · 입력값 보존과 계측의 범위

‘기존 요소의 글자만 수정 0개’는 최종 글자가 바뀌지 않았다는 뜻이 아닙니다. 전체 교체는 바뀐 글자를 담은 새 요소를 만들므로 생성 작업으로 집계합니다. 전체 요소 수에는 목록 ul과 배송 요청 input도 포함하며 텍스트 노드는 제외합니다.

이 배송 요청은 입력칸 자체에 보관한 값입니다. HTML 구조가 같아도 입력칸에 현재 남은 값은 다를 수 있습니다. 전체 교체 방식도 배송 요청을 별도 상태에 저장하고 복원하면 보존할 수 있습니다. 이 실험은 기존 DOM을 재사용하는 효과를 보여줍니다. 실제 React의 상태·컴포넌트 관리 이점은 Phase 2에서 이어서 확인합니다.

시간 단위 ms는 1/1,000초입니다. 비교 실행 시 두 방식의 실제 작업을 한 번씩 자동 측정합니다. 측정용 목록을 추가로 만들거나 반복 실행하지 않습니다. 실행 순서는 매번 교대합니다. 전체 교체는 새 DOM 생성·교체, Diff·Patch는 차이 계산·DOM 수정 시간을 포함합니다. 공통 VDOM 입력 준비·색상 표시·결과 검사는 제외합니다.

이 시간은 실제 결과 영역을 수정하는 JavaScript·DOM 처리 구간입니다. 변경 후 브라우저가 수행하는 배치 계산·화면 그리기를 포함한 전체 시간은 아닙니다. 단일 측정은 편차가 크고, 작은 값은 측정 해상도 때문에 0.000 ms로 나올 수 있습니다. 같은 조건을 다시 확인하려면 처음 상태로 돌아간 뒤 실행하세요.

Diff가 계산한 변경 명령 
[]

전체 교체는 React를 사용하지 않는 모든 방식을 대표하지 않습니다. 직접 DOM을 부분 수정하는 방법도 있습니다. Diff는 비교 계산 비용이 있어 항상 더 빠른 것은 아닙니다. 이 결과는 이 Mini React 구현과 현재 실험 조건에 대한 결과입니다.
