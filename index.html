              01 / PATCH 한 번 추적하기
              
“안녕”을 “반가워”로.

              

                Phase 1에서 문장을 바꾸고 Patch를 누르세요. 변경 목록에서 TEXT를
                찾습니다.
              

              controller.commit()
→ domToVNode(testRoot)
→
                diff(previous, next)
→ patch(actualRoot, patches)
→
                history.push(next)
              

                읽을 파일: playground/controller.js → vdom/dom-to-vnode.js →
                diff.js → patch.js
              

            

            

              02 / STATE 한 번 추적하기
              
작업을 추가하면?

              

                두 setter가 같은 microtask에서 모여 한 번 update됩니다. 함수는
                다시 실행돼도 hooks 배열은 인스턴스에 남습니다.
              

              onSubmit → setTasks / setDraft
→
                FunctionComponent.schedule()
→ update() → App()
→
                diff() → patch()
→ Effect cleanup / 실행
              

                읽을 파일: demo/app.js → runtime/hooks.js →
                function-component.js
              

            

            

              03 / 여섯 가지 DIFF
              
변경을 분류합니다.

              

                
INSERT

                
새 자식 추가

                
MOVE

                
고유 key를 가진 기존 자식 이동

                
REMOVE

                
기존 자식 삭제

                
REPLACE

                
태그 또는 노드 종류 교체

                
TEXT

                
텍스트 값 수정

                
PROPS

                
속성·프로퍼티·이벤트 변경

              

              

                고유한 key를 가진 형제는 key로 대응시켜 MOVE로 이동합니다. key가
                없거나 불완전하면 인덱스로 비교합니다.
              

            

            

              04 / HOOK의 약속
              
순서가 상태의 주소입니다.

              

                Hook은 루트의 최상위에서 매번 같은 순서로 호출하세요.
                조건문·반복문 안에서 호출하지 않습니다.
              

              hooks[0] → tasks
hooks[1] → draft
hooks[2] → query
…
자식
                컴포넌트 → props만 사용
              

                자식 Hook 호출과 Hook 종류·개수 변경을 검사합니다. 같은 종류
                Hook끼리 위치를 바꾸는 오류는 자동 검출할 수 없습니다.
